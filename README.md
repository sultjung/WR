# 이라크 주간상황보고서

㈜한화 건설부문 비스마야 신도시 사업을 위한 아랍어 현지뉴스 수집·정세분석·주간보고서 작성 지원 시스템입니다.

## 확정된 운영 원칙

- 공개 저장소 및 공개 GitHub Pages 사이트
- 아랍어 원문 기사만 수집
- 기본 표시기간 30일, 보고서 기본기간 7일, 최초 검증기간 14일
- 매일 06:20 KST 자동 수집, 필요 시 12:30 KST 추가 수집
- 수집·원문 URL 확정·본문 추출 단계에서는 AI를 사용하지 않음
- 최종 기사 선택과 문장 검토는 사람이 수행
- 아랍어 기사 전문과 원문 URL을 함께 데이터에 보관
- 카드 표시를 위해 모든 기사를 전문 번역하지 않음
- 보고서 생성은 사용자가 선택한 기사만 사용
- 유사기사는 보고서 생성 전에 주제 군집으로 다시 통합
- 카테고리 순서와 카테고리 내부 시간순을 코드와 검증기로 강제
- 실패한 보고서 실행은 기존 `reports/latest.docx`를 덮어쓰지 않음

## 기사 카드 처리 방식

기사 카드는 번역과 요약을 한 번에 수행하지 않고 다음 두 단계를 분리합니다.

1. 저장된 아랍어 원문에서 확인된 사실을 아랍어 구조화 데이터로 추출
2. 구조화된 사실만 입력해 한국어 제목과 카드 요약 작성

1단계는 인물·기관·장소·날짜·수치·행동·결과를 보존하고 기사 외부의 전망이나 해석을 추가하지 않습니다. 2단계에는 아랍어 원문 전체가 전달되지 않으므로 번역과 요약이 섞이지 않으며, 전문 번역 출력 토큰도 발생하지 않습니다.

처리 결과는 다음 필드로 분리해 저장합니다.

- `originalTextArabic`: 수집 당시 아랍어 원문 전문
- `articleUrl` / `canonicalUrl`: 출처 확인용 원문 주소
- `cardFacts`: 아랍어 원문에서 추출한 구조화 사실
- `card`: 구조화 사실을 바탕으로 작성한 한국어 제목과 카드 요약
- `relatedTitle`: 동일 사건으로 묶인 관련기사의 한국어 제목

원문 내용이 바뀌면 `cardFacts`와 `card`를 대기 상태로 전환해 순차적으로 다시 생성합니다. 처리 한도를 넘은 대기 항목은 다음 실행에서 이어서 처리하며, 이미 생성된 표시 문구는 새 결과가 준비될 때까지 유지합니다.

## 자동 실행과 수동 재처리

- `Collect Arabic News`: 정기 수집과 전체 파이프라인을 담당합니다.
- `Generate Facts-First Article Cards`: 기존 기사 카드와 관련뉴스 제목만 다시 만들 때 수동으로 실행합니다.
- `Re-score Article Importance`: 기존 기사 중요도만 다시 평가할 때 수동으로 실행합니다.
- `Generate Weekly Report`: 사이트에서 생성한 저장소 소유자 요청을 받아 최종 Word 보고서를 만듭니다.
- `Validate WR Project`: 최신 커밋만 검증하며, 이전 검증이 진행 중이면 취소합니다.

카드 생성, 중요도 평가, 최종 보고서 편집은 OpenAI API 비용이 발생합니다.

## 저장소 데이터 관리

GitHub Pages가 직접 사용하는 영구 데이터는 `data/articles.json`입니다. 다음 파일은 수집 과정에서 생성되는 중간 산출물 또는 진단 자료이므로 실행 중에는 검증하지만 저장소에는 커밋하지 않습니다.

- 발견·URL 복구·URL 해석 단계 데이터
- 사건 그룹 진단 데이터
- 이라크 범위 및 카테고리 필터 진단 데이터
- 해외 현지기사 혼입 감사 데이터
- 보고서 생성 중간 입력·AI JSON·검증 전 Word 파일

## 선택 기사와 최종 보고서

카드 요약은 기사를 고르는 용도로만 사용합니다. 선택 기사의 보고서 작성 단계에서는 `card.summaryKo`를 원문처럼 재사용하지 않고, 저장된 `originalTitleArabic`, `originalTextArabic`, `cardFacts`를 다시 불러옵니다.

생성 흐름은 다음과 같습니다.

1. 사이트에서 요약이 완료된 기사 1~40건 선택
2. 보고일과 보고기간 확인
3. `선택 기사로 보고서 생성` 버튼 클릭
4. 열린 GitHub 이슈를 저장소 소유자 계정으로 등록
5. 선택 기사·기간·원문 상태 재검증
6. 기존 사건그룹, 제목 유사도, 핵심 사실, 인물·기관 중복을 이용해 보고서용 주제 군집 생성
7. 같은 주제 군집의 기사들은 한 보고서 항목으로 강제 통합
8. 오피넷에서 보고일 기준 D-2·D-1 Dubai·Brent·WTI 가격 조회
9. 고급 모델이 군집별로 실제 보고서 문체의 구조화 JSON 작성
10. 정치권 동향 → 테러·치안 → 경제 → 국제사회 순서로 배치하고, 각 섹션 안에서는 날짜 오름차순으로 재정렬
11. 고정 Word 템플릿에 문장·테러 표·유가 표 삽입
12. 유사기사 분리 여부, 카테고리 배치, 시간순, 기사 누락·중복, 날짜·표·유가값 검증
13. 모든 검증 통과 후에만 `reports/latest.docx`와 날짜별 보관본 교체

선택 기사 수가 많을 때는 입력 전체 길이가 과도하게 늘지 않도록 기사별 아랍어 원문 길이를 자동 조절합니다. 구조화 사실과 제목·요약은 모두 유지하며, 최대 40건을 선택해도 한 번의 최종 편집이 안정적으로 수행되도록 전체 입력 예산을 제한합니다.

완료된 최신 파일은 GitHub Pages의 `reports/latest.docx`에서 내려받을 수 있습니다. 날짜별 보고서는 `reports/generated/YYYY/MM/`에 보관됩니다.

## 보고서용 유사기사 통합

웹사이트의 관련기사 묶음이 완벽하지 않더라도 최종 보고서 단계에서 다시 통합합니다.

- 기존 `eventGroup.groupId`가 같은 기사는 동일 주제로 묶음
- 같은 섹션이고 3일 이내에 발행된 기사 중 제목 유사도가 높은 기사를 묶음
- 핵심 사실과 인물·기관이 함께 겹치는 기사도 보수적으로 묶음
- 하나의 군집에 포함된 모든 기사 ID가 최종 보고서의 동일 항목에 들어갔는지 검증
- 같은 기사 ID가 여러 항목에 중복 사용되거나 군집이 나뉘면 보고서 생성을 실패 처리

군집이 달라도 고급 모델이 실질적으로 같은 사건으로 판단하면 추가 통합할 수 있습니다. 반대로 코드가 만든 동일 군집을 여러 항목으로 쪼개는 것은 허용하지 않습니다.

## 카테고리 및 시간순 원칙

최종 Word 보고서는 다음 순서를 고정합니다.

1. 이라크 국내 상황
   - 정치권 동향: 비스마야, NIC, 총리, 정부, 의회, 투자·주택정책
   - 이라크 주간 테러 상황
2. 경제
3. 국제사회
4. 그룹 / 건설에 미치는 영향

각 카테고리 내부 항목은 선택 기사들의 실제 발행일 기준 오름차순으로 코드가 다시 정렬합니다. 같은 날짜에는 중요도가 높은 항목을 먼저 배치합니다. AI가 다른 순서로 응답하더라도 Word 생성 전 재정렬하며, 최종 검증기가 시간순과 카테고리 배치를 다시 확인합니다.

## 국제사회 기사 재분류 원칙

`international`은 단순히 외국이 등장하는 기사를 뜻하지 않습니다. 이라크가 사건의 직접 당사자가 아니고, 외부 국제정세가 이라크·사업환경에 미치는 영향을 확인해야 하는 기사만 국제사회에 남깁니다.

- 제목에 이라크가 직접 등장하거나 도입부에서 이라크 정부·총리·부처·대표단이 행위자로 등장하면 국내 카테고리 재분류를 우선 적용
- 정상·정부 간 회담, 전략적 파트너십, 양국관계, 외교협정과 포괄적 다분야 협약은 `politics`
- 무역·투자·석유·가스·에너지·전력·수자원·개발도로·철도·항만·재건·주택·인프라가 중심이면 `economy`
- 국경안보·테러·군사협력·공격·군 철수·국방 문제가 중심이면 `security`
- 이라크가 본문의 참고 사례나 잠재 영향 대상으로만 언급되는 글로벌 유가·호르무즈·미국·이란·역내 정세 기사는 `international` 유지

예를 들어 `터키-이라크, 전략적 파트너십 강화 위해 다분야 협약 체결`은 이라크와 터키 정부가 직접 당사자인 양국관계 기사이므로 기본적으로 정치권 동향으로 분류합니다. 협약의 핵심이 무역·투자·에너지·수자원·교통사업으로 명확히 집중된 경우에는 경제로 분류합니다.

이 규칙은 뉴스 수집 단계에서 기존 `international` 기사를 재분류한 뒤 사건그룹·중요도·카드 요약을 다시 계산하는 데 적용됩니다. 최종 보고서 생성 직전에도 같은 규칙을 한 번 더 적용해 저장 데이터의 과거 분류가 남아 있더라도 정치·경제·치안 섹션으로 바로잡습니다.

## 보고서 생성 보안

GitHub Pages에는 OpenAI API 키를 넣지 않습니다. 사이트 버튼은 선택 기사 ID와 보고기간만 포함한 GitHub 이슈 작성 화면을 열며, 실제 AI 호출과 Word 생성은 GitHub Actions에서 수행합니다.

`Generate Weekly Report`는 다음 조건을 모두 만족할 때만 실행됩니다.

- 이슈 제목이 `[REPORT]`로 시작
- 이슈 작성자가 저장소 소유자
- 선택 기사 ID가 현재 `data/articles.json`에 존재
- 대표기사이며 카드 요약이 최신 완료 상태
- 아랍어 원문이 300자 이상
- 기사 날짜가 보고기간 안에 있음
- 선택 기사 수가 40건 이하

## GitHub 설정

저장소 Secret:

- `OPENAI_API_KEY`: 기사 카드 및 최종 보고서 생성용 API 키

선택적 Repository Variables:

- `REPORT_MODEL`: 최종 편집 모델. 기본값 `gpt-5.1`
- `REPORT_MODEL_FALLBACKS`: 기본값 `gpt-5,gpt-4.1`
- `REPORT_REASONING`: 기본값 `high`

모델 이름은 계정에서 실제 사용 가능한 모델에 맞춰 Repository Variables에서 변경합니다.

## 국제유가 원칙

- 출처: 오피넷(한국석유공사) 국제유가 원유 조회
- 단위: USD/Bbl
- 대상: 보고일 D-2, D-1
- 열 순서: 두바이유, 브렌트유, 서부텍사스유(WTI)
- 두 날짜 중 하나라도 공식 값이 없으면 보고서 생성을 중단
- 가까운 날짜로 대체하거나 임의 값을 넣지 않음

## Word 양식

`scripts/build-weekly-report-template.py`가 매 실행마다 동일한 `templates/weekly-report-template.docx`를 만들며, A4 용지, 여백, 바탕체 계열 글꼴, 제목·본문·세부내용·분석문 스타일, 페이지 번호가 고정돼 있습니다. AI는 Word 서식을 만들지 않고 아래 내용 구조만 반환합니다.

- 정치권 동향
- 주간 테러 사건과 유형별 집계
- 경제·국제유가 동향
- 국제사회
- 그룹 / 건설에 미치는 영향
- 필요한 경우 내각회의 등 복수 안건 표

`render-weekly-report.py`가 이 구조를 템플릿에 삽입하므로 AI 응답 길이에 따라 표 너비나 글꼴이 임의로 바뀌지 않습니다.
